# N2 Diagram and Budgets

## What it is

The N2 model is an OpenMDAO model of the rover. Each subteam's parts are in the
model, and the model adds them up into five budgets so we can see if the rover
fits its limits. If a team wants to change something (heavier motor, more
cameras), we change the number and re-run to get a rough estimate of how it
affects everything else before asking the other teams.

It also draws an **N2 diagram**: a grid showing which subsystem sends numbers
to which. Subsystems are on the diagonal, connections are the squares off the
diagonal.

Code is in `data/N2-Diagram`.

## Budgets

| Budget  | Total                     | Limit                        |
|---------|---------------------------|------------------------------|
| mass    | total weight (kg)         | `MAX_WEIGHT` in `N2.py`      |
| power   | power drawn at once (W)   | battery max output           |
| storage | data written to disk (MB/s) | no limit                   |
| compute | GPU %, CPU %, RAM GB      | `gpu_limit`, `cpu_limit`, `ram_limit` in `specs.csv` |
| network | data sent to base (Mbps)  | `link_Mbps` in `specs.csv`   |

Every budget takes one value from each subsystem, always in the same order:
mechanical, science, electrical, software.

## How to run

First time:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Every time:

```bash
source .venv/bin/activate
cd data/N2-Diagram
python3 N2.py
```

In VS Code you can press Run on `N2.py` instead. `.vscode/settings.json` makes it
run from the file's folder with the `.venv` Python.

Common errors:

| Error | Cause | Fix |
|-------|-------|-----|
| `No module named 'openmdao'` | wrong Python | activate `.venv`, or select it in VS Code (Cmd+Shift+P, Python: Select Interpreter) |
| `No such file or directory: 'specs.csv'` | running from the wrong folder | `cd data/N2-Diagram` first |
| `KeyError: Variable '...' not found` | a path in `specs.csv` doesn't match the code | fix the path in `specs.csv` or the name in the `.py` file |

## How to read the output

### Budget table

```
Budget    Units      Total    Left  Status
--------  -------  -------  ------  ----------------
Mass      kg          1.59   48.41  GOOD
Power     W          64.38  -64.38  BAD - over limit
```

- **Total**: what everything on the rover uses
- **Left**: limit - total
- **GOOD**: left is 0 or more, under the limit. Left is the spare.
- **BAD**: left is negative, over the limit by that much

A budget can show BAD just because its limit is still `-0.0` in `specs.csv`.
Check the values before worrying about it.

### N2 diagram

`n2_diagram.html` opens in the browser.

- **Diagonal blocks**: subsystems. Click to expand and see their parts.
- **Squares above the diagonal**: data flowing forward (normal)
- **Squares below the diagonal**: feedback loops. These need a solver, so tell
  systems if one shows up.
- **Inputs with no connection** are fed from `specs.csv`

## How to update it

### Change a value

Edit the row in `specs.csv` and re-run. You don't need to touch any `.py` file.

```
path,value,units
software.jetson_orin_agx.jetson_power,60,W
```

- `path` has to match the code exactly
- `-0.0` means not filled in yet
- Blank units are for counts and %
- If you edit in Excel, save as **CSV UTF-8**, not `.xlsx`

### Add a part

Only edit your own subsystem file. `N2.py` stays the same.

1. Add the part as a component in your group, for example in `software.py`:

   ```python
   self.add_subsystem('lidar', om.ExecComp(
       ['mass = 1.0 * lidar_mass',
        'elec_power = 1.0 * lidar_power'],
       lidar_mass={'units': 'kg'},
       lidar_power={'units': 'W'},
       mass={'units': 'kg'},
       elec_power={'units': 'W'}
   ))
   ```

2. Add it to your group's `total` (`input_names`) and connect it:

   ```python
   self.connect('lidar.mass', 'total.m_lidar')
   self.connect('lidar.elec_power', 'total.p_lidar')
   ```

3. Add its values to `specs.csv`:

   ```
   software.lidar.lidar_mass,-0.0,kg
   software.lidar.lidar_power,-0.0,W
   ```

4. Re-run and check the totals changed.

## Rules

- **Every input needs a value.** Either `connect` it or put it in `specs.csv`.
  Unconnected inputs silently default to 1.0, which makes totals wrong.
- **Each group's `total` must output** `mass`, `elec_power`, `data_MBps`,
  `net_Mbps`, `gpu_pct`, `cpu_pct` and `ram_GB`. Electrical's also outputs
  `max_power`. `N2.py` connects to these.
- **`AddSubtractComp` needs at least 2 inputs** per equation. For a single
  value use `ExecComp` with `1.0 *`.
- **Power is in W, not A.** Parts run at different voltages, so only watts can
  be added together.
- **Units**: OpenMDAO checks units between components, not inside formulas.
  It has no byte or % units, so those go in the variable name (`_MBps`,
  `_pct`). Mbps is bits, MB/s is bytes (1 MB/s = 8 Mbps).
- **Names** can only use letters, numbers and underscores, and can't start
  with a number.
- **Comments** are Epytext docstrings (`@param`, `@return`, `@note`) so they
  show on hover.
